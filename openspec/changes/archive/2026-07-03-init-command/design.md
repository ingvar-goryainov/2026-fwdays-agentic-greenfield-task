## Context

`agents-lint scan` (from the `scan-command` capability) reads an AGENTS.md
file and validates it against rules S001-S005 defined in
`internal/lint/rules`. Those rules are `apply`-complete and stable. `init`
needs to produce output that satisfies all of them without duplicating or
hand-guessing their logic, since any drift between "what init generates" and
"what scan checks" would make the tool self-contradictory on its own output.

The CLI already follows a pattern in `cmd/agents-lint/cmd/scan.go`: a
testable `run<Name>(w io.Writer, ...) (exitCode int, err error)` function
plus a thin Cobra `RunE` wrapper that owns `os.Exit`. `init` should follow
the same shape for consistency and testability.

## Goals / Non-Goals

**Goals:**
- `agents-lint init [path]` writes a minimal AGENTS.md skeleton to `path`
  (default `./AGENTS.md`) that passes S001-S005 with zero findings.
- Guard against silently clobbering an existing AGENTS.md.
- Prove the "always passes" guarantee with a test that runs the real rule
  set (not a hand-written assertion) against the generated content.

**Non-Goals:**
- No `--fix` behavior (repairing an existing broken AGENTS.md) — out of
  scope per project boundaries; `init` only ever writes a fresh skeleton.
- No templating/customization flags (e.g. choosing agent name, number of
  agents) — the skeleton is intentionally static and minimal.
- No interaction with `.agents-lint.yaml` config — `configuration-support`
  is a separate, not-yet-built capability; `init` always validates against
  default rule severities.

## Decisions

**Skeleton lives in its own package, not inline in the cmd layer.**
`internal/lint/skeleton` exports a `Content() string` (or `[]byte`) function
returning the static AGENTS.md text. This mirrors the project's
library-first convention (no `fmt.Print` in `internal/`) and lets the
regression test import both `skeleton` and `rules` directly, without going
through Cobra or file I/O, to assert `rules.Run` on the generated bytes
produces zero error-severity findings.
- Alternative considered: inline the string literal in
  `cmd/agents-lint/cmd/init.go`. Rejected because `internal/` is where
  reusable, testable logic belongs per CLAUDE.md conventions, and cmd/
  packages should stay thin wrappers.

**Skeleton content, concretely:**
```markdown
---
name: example-project
---

## Agent

### Example Agent

Role: Describe what this agent is responsible for.

Instructions: Describe how this agent should behave.
```
This satisfies S005 (valid YAML frontmatter), S002 (`## Agent` section),
S003 (name + role + instructions on the one agent block), and S004
trivially (only one agent name, so no duplicates possible). S001 is
satisfied by construction once the file is written.

**Overwrite protection defaults to refuse, with `--force` to override.**
`init` checks whether a file already exists at the target path before
writing. If it exists and `--force` was not passed, it returns a non-zero
exit and an actionable error rather than overwriting silently.
- Alternative considered: always overwrite (simplest). Rejected — a user's
  hand-authored AGENTS.md is high-value content; silent data loss is a
  worse failure mode than requiring an explicit flag.
- Alternative considered: prompt interactively for confirmation. Rejected —
  CLI tools in this project are expected to run non-interactively (e.g. in
  CI), and an interactive prompt would hang or need a `--yes` escape hatch
  anyway, which is just `--force` by another name.

**Exit code / error handling matches `scan`'s pattern.** `runInit` returns
`(exitCode int, err error)`; write failures and the "file exists" guard both
produce exit code 1 with a wrapped, actionable error message
(`fmt.Errorf("init %s: %w", ...)`), consistent with the project's error
conventions.

## Risks / Trade-offs

- [Risk] Skeleton drifts from rules if a future rule (e.g. a new S00N) is
  added and the skeleton isn't updated. → Mitigated by the regression test
  that runs the real `rules.DefaultRules()` (+ S001) against the generated
  content; any new rule that the skeleton fails will fail CI immediately.
- [Risk] `--force` silently destroys a hand-edited AGENTS.md. → Mitigated by
  requiring the flag to be explicit (no default-true behavior) and printing
  a clear success message naming the path written, so the action is visible
  in command output/logs.
